## 2026-05-20
- **Production readiness — env validation, deep health, structured logs, request IDs, boot banner**:
  - **`server/config.js`**: zod-based boot-time validator. Required vars (`DATABASE_URL` in non-test), bounded ranges (`PORT`, `NEWS_DRAFT_MIN_CONFIDENCE`), coerced types (PORT/intervals → number). Production-only invariant rejects boot if `DEMO_PASSWORD` is still the seed default. Bad config exits the process with a precise multi-line error before serving any traffic.
  - **`server/logger.js`**: zero-dep structured logger — single-line JSON in production (ready to ship to Loki/Datadog/CloudWatch), colored pretty-print in dev, silent in test (errors still to stderr).
  - **Request ID middleware** in [server/index.js](server/index.js): every request gets a 16-hex `req.id` (or the incoming `X-Request-Id` if upstream supplied one), echoed via `X-Request-Id` response header. 500 responses include `requestId` in the JSON body so users can quote it.
  - **Structured HTTP log middleware**: replaces the bare `console.log(method path)` line. Logs on `res.on('finish')` with `{reqId, method, path, status, ms, user}`. Skips `/health` to keep aggregators clean.
  - **Deep `/health`**: `await prisma.$queryRaw\`SELECT 1\`` then returns `{ok, uptimeMs, dbMs, env}` (200) or `{ok: false}` (503) so orchestrators can replace stuck containers. Probed live: dbMs=1, uptimeMs reported correctly.
  - **Boot banner**: single structured `info boot port=... env=... node=... mistral=... googleOAuth=... newsScheduler=...` line so ops know what mode the process is in from line 1 of the logs.
  - **Error handler**: unhandled throws now log with `{reqId, method, path, user, err}` context so they're correlatable in aggregator searches.
  - **[DEPLOY.md](DEPLOY.md)**: env table expanded with new vars + the production password rule; ops section documents the new health shape, request IDs, and the structured log format.
  - Tests: 9 new in [tests/api.test.js](tests/api.test.js) (health shape, request ID generation, upstream-ID echo, dev defaults, prod DEMO_PASSWORD rejection, missing DATABASE_URL rejection, out-of-range NEWS_DRAFT_MIN_CONFIDENCE rejection, scheduler-flag derivation). **117/117 backend tests pass.**

New `POST /api/me/claim-all` loops through claimable positions in one shot — idempotent on the second call. MarketDetail's claim/propose/dispute/finalize handlers now refresh `actions` so the badge updates instantly. Side-fix: `rateLimit()` is a no-op under `NODE_ENV=test` so the in-memory bucket doesn't 429 the test suite from a single loopback IP. Tests: 6 new in [tests/api.test.js](tests/api.test.js) (zero-state, claimable surfacing, needs-proposal owner flow, dispute-window-with-stake, claim-all idempotence, auth-required). **110/110 backend tests pass.** Verified end-to-end in browser: Alice's two waiting-for-propose markets surfaced → admin finalized one in her favor → claim-all credited 288 chips instantly → badge 2→1, Action Center shrank to remaining needs-proposal item, no console errors.
